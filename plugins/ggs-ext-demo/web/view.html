GGX Demo the ggx/2 plugin format's worked example

Every button below is one capability of the extension platform, used exactly the way a real plugin uses it. The plugin's README.md walks through the same ground file by file.

1 · The page context

Acquired once at boot: api.ready resolves with which extension and page this is, the parameters the opener passed, and the display language.

2 · Backend commands api.request('backend.run', …)

Every button asks the plugin's process backend (a warm sibling binary speaking JSON lines over stdio). The backend keeps state between calls, so Tick counts up; Fail shows how an error arrives.

3 · Host services api.request('notify' | 'showInputBox' | 'showQuickPick' | 'clipboard.writeText', …)

The same request channel reaches the workbench itself — notifications, quick inputs, the clipboard, workbench commands.

4 · Sibling pages api.request('pages.open', …)

A package can ship several pages (the manifest's pages registry); any of them can open another with parameters.
