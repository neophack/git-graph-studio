## 1. 问题盘点

远程现在有两种形态（ggs-remote-plan.md §22.5）：**副本**（默认——浏览器看 PC 窗口的 DOM 副本，输入回放进 PC）与**独立界面**（`?frontend=1`，或手机连接一个 PC 屏幕上正显示的窗口时自动进入——浏览器跑自己的工作台，手机上是手机外壳）。两种形态各有一组问题：

| # | 现象 | 根因 | 位置 |
| - | ---- | ---- | ---- |
| Q1 | 远程"打开文件夹"选不到 PC 上的文件夹 | 独立界面：对话框垫片走 `remoteFilePicker` → `list_dir`，而路径门禁只放行已打开文件夹内的路径，PC 其余目录一律列空；选完后 `open_folder` 又被门禁拒绝（"remote session cannot open new folders"）。副本：点击回放进 PC，弹的是 **PC 屏幕上**的原生对话框，B 看不见；B 能看到的文件选择器只有"上传到此处"那一个——那个选的本来就是 B 的文件 | `src/remote/tauriShim/dialog.ts`、`src/remote/remoteFilePicker.ts`、`src/remote/pathGate.ts` 的 `open_folder` 规则、`src/workbench/lifecycle.ts` 的 `pickFolder` |
| Q2 | 窗口切换器的"新窗口…"选文件夹同样列空 | 同 Q1，复用了 `pickRemotePath` | `src/remote/windowSwitcher.ts` |
| Q3 | 远程菜单里有用不了的项：打开文件…、打开工作区…、打开最近（会话里都被门禁拒绝）；副本里还有"新窗口"（新窗口开在 PC 上，B 看不到）、开发者工具、退出 | 菜单只裁剪了"新窗口"与"开发者工具"两项，且只对独立界面生效；副本显示的是 PC 菜单原样 | `src/workbench/menus.ts` |
| Q4 | 本地与远程按钮不对应：远程有上传/下载，本地的资源管理器也有（2026-10-13 起的导入/导出行），PC 被观看时又隐藏 | 传输行是"每个环境一套词汇"，但本地是否需要它从未定过 | `src/features/explorer/transfer.ts` 的 `transferMenuShown` |
| Q5 | 副本是 PC 界面的 1:1：桌面用浏览器看到的是缩放的 PC 窗口，手机看到的是 PC 窗口临时换上的手机外壳；本地用户与远程用户争夺同一个窗口尺寸与焦点 | §22 的副本是一张画片，一个窗口一棵 DOM | `src/remote/mirror/*` |
| Q6 | 流量：副本按 DOM 变更计费，经济化后仍是"PC 画面上一切可见变化"的函数（Claude 流式 7 KB/12 s，虚拟列表滚动 6.8 KB/2 s）；操作同步（§22.7）只要约 96 B/条 | 副本同步的是像素的替身，而不是操作与数据 | ggs-remote-plan.md §22.7、§22.8 的实测 |

## 2. 目标与非目标

**目标**

- G1 远程选择的永远是 **PC（A）** 上的文件夹；打开它的是 PC 上的窗口。（P0，已落地）
- G2 所有远程端（手机、平板、另一台电脑的浏览器）**默认**运行同一种远程界面——手机外壳的页面模型，宽屏时多栏排版——而不是 PC 窗口的副本。
- G3 本地与远程各有一份**命令配置**：远程没有"打开文件 / 打开工作区 / 新窗口 / 开发者工具 / 退出"这类只在 PC 屏幕前有意义的按钮，本地没有"上传 / 下载"；两边共有的命令行为一致。
- G4 流量按"操作与数据"计费：每类状态归入"必须同步 / 按需拉取 / 只在本端"三档之一，默认会话（空闲 + 浏览 + 编辑一个文件）的下行有明确预算。
- G5 PC 屏幕前的用户与远程用户互不争夺窗口：远程端不再改 PC 窗口的尺寸、焦点与外壳。

**非目标**

- 不改 `ggs-remote/1` 协议的帧格式、守护进程、Hub 与沙箱规则。
- 不删副本模式：它变成远程端一个显式的"查看 PC 屏幕"功能（§8）。
- 不在远程端复刻原生对话框的全部能力（例如任意磁盘的"另存为"到 B 本机——那是"下载"）。

## 3. 设计原则

1. **远程是一个客户端形态，不是 PC 界面的遥控器。** 远程端跑自己的工作台代码（与桌面同一份 `src/workbench`），用自己的外壳与命令配置；PC 上的窗口是数据与进程的宿主，不是远程端要看的画面。
2. **PC 的资源由 PC 选择，B 的资源由 B 选择。** 打开文件夹、新窗口的文件夹、"另存为"的位置——选的是 PC 磁盘，经守护进程或实例浏览；上传选的是 B 的文件，下载落到 B 的磁盘。两类选择器的名字与图标不同，永不混用。
3. **原生对话框只属于 PC 屏幕前的人。** 远程端每一个会弹原生对话框的入口要么有远程实现（PC 文件夹浏览器、页内确认框），要么在远程命令配置里不存在。
4. **同步操作与数据，不同步画面。** 跨端过线的是"打开了哪个文件、切到哪个视图、文档改了什么、终端输出了什么"；布局尺寸、滚动位置、动画、悬停、光标闪烁各端自己画。
5. **能按需的不推送。** 一端没在看的东西不过线：未展开的目录、未打开的文件、未显示的面板、折叠的 SCM 组。
6. **扩展的 webview 只在 PC 上活一份**（ggs-remote-plan.md §22.6 不变）：Claude Code 对话、Git Graph 页面在远程端是该页面的流式副本——这是唯一保留"画面同步"的地方，因为页面状态只存在于那一份 JS 里。

## 4. 远程外壳：一种界面，按宽度排版

所有远程端运行 `src/remote/shell.ts` 的远程外壳（今天只在手机宽度生效）。页面模型不变（`pages.ts`：文件、编辑器、更改、扩展页、终端……），排版按视口宽度分三档：

| 档 | 宽度 | 排版 | 说明 |
| -- | ---- | ---- | ---- |
| 手机 | < 600 px | 单栏全屏页 + 底部导航 + 抽屉（现状） | 现有 `appBar` / `bottomTabs` / `navDrawer` / `actionSheet` 原样 |
| 平板 | 600–1100 px | 左侧导航栏（图标）+ 一个页面；编辑器页可与一个侧页并排 | 底部导航改为左侧导航栏；动作仍走 action sheet（触屏优先） |
| 桌面浏览器 | > 1100 px | 导航栏 + 侧页 + 编辑器 + 可选底部面板 | 外观接近桌面工作台，但**菜单与按钮来自远程命令配置**（§5），上下文菜单用桌面浮动菜单而非 action sheet |

要点：

- 外壳的选择**只看远程/本地**，不看宽度：桌面浏览器也是远程外壳，只是排版宽。今天的 `data-form-factor` 继续驱动排版，`data-remote-shell` 成为所有远程页面的常量。
- 标题栏：远程端没有窗口控制按钮、没有 PC 的菜单栏；左上是窗口名（PC 窗口的标题 + 主机名），点击即窗口切换器（§6.2）；右侧是连接状态、省流开关、用户菜单（设备、退出登录）。
- 本地 PC 窗口**永远**是桌面界面：`phoneShell.ts` 让 PC 窗口临时换上手机外壳、`remote_mirror_fit` 改 PC 窗口尺寸的路径只在显式的"查看 PC 屏幕"（§8）里存在。

## 5. 命令配置：本地与远程各有一套

命令注册表（`src/platform/commands.ts`）不分叉——同一个命令 id 在两端行为一致。分的是**哪些命令出现在菜单、按钮、命令面板里**：每个命令带一个可见性 `profiles: ('desktop' | 'remote')[]`，缺省两端都有。菜单、标题栏、抽屉、action sheet、命令面板统一按当前配置过滤（取代 `menus.ts` 里逐项的 `hook('session').remote()` 判断）。

| 命令 | 本地 | 远程 | 远程上的行为 / 说明 |
| ---- | :--: | :--: | ---- |
| 新窗口 `workbench.newWindow` | ✓ | ✗ | 远程用窗口切换器的"在新窗口打开文件夹…"（§6.2） |
| 打开文件夹 `workbench.openFolder` | ✓ | ✓ | 远程：PC 文件夹浏览器 → 进入已显示该文件夹的窗口，或 SPAWN 一个（P0 已落地） |
| 打开文件… `workbench.openFileStandalone` | ✓ | ✗ | 远程打开文件 = 文件页 / 快速打开（Ctrl+P），只在已打开文件夹内 |
| 打开工作区… `workbench.openWorkspace` | ✓ | ✗ | 待定：可做成"PC 浏览器选 `.ggs-workspace` → SPAWN"（§10 Q-c） |
| 打开最近 | ✓ | 并入 | 远程的最近文件夹来自守护进程 `recent.json`，并入打开文件夹浏览器的顶部（P0 已落地） |
| 关闭文件夹 | ✓ | ✗ | 远程端关闭的是"这个窗口"——窗口切换器里的"关闭窗口"（有未保存文件时确认） |
| 退出 `workbench.exit` | ✓ | ✗ | 远程端退出 = 退出登录（用户菜单） |
| 开发者工具 | ✓ | ✗ | 现状 |
| 键盘快捷方式页、编辑器布局子菜单 | ✓ | 桌面浏览器档 ✓ / 其他 ✗ | 现状对手机已裁剪，平板同手机 |
| 上传文件 / 文件夹到此处 | ✗ | ✓ | 选 B 的文件，分块续传到 PC（现状） |
| 下载 / 下载为 Zip | ✗ | ✓ | 落到 B 的磁盘（现状） |
| 窗口切换器 `remote.switchWindow` | ✗ | ✓ | 现状 |
| 查看 PC 屏幕 `remote.liveView` | ✗ | ✓ | §8 |
| 省流模式 `remote.toggleDataSaver` | ✗ | ✓ | 现状 |
| 设置 | ✓ | ✓ | 远程用手机设置页（`settingsPage.ts`），平板/桌面浏览器档可用桌面对话框 |

**本地的上传/下载（Q4）**：本地的资源管理器"导入 / 导出"行（`fs_import` / `fs_export`）与远程的"上传 / 下载"词汇不同、语义也不同（PC 磁盘到 PC 磁盘），所有者的表述是"本地软件没有上传下载"。建议：本地右键菜单不再显示传输行（OS 的拖放与资源管理器已覆盖"把文件拷进工作区"），`fs_import` / `fs_export` 两个命令保留在命令面板里，供需要的人用——见 §10 Q-a。

## 6. 文件夹、窗口与传输

### 6.1 打开文件夹（P0，已落地）

- 守护进程新增 `GET /api/browse?path=`（`extensions-src/ggs-remote/daemon/src/http/browse.rs`）：需要会话；只返回一个目录的**子文件夹名**（不含文件）；空路径从主目录开始，附带起点列表（主目录、各盘符 / `/`）；`folderInput` 关闭时 403——和窗口选择页的"输入路径"行同一条信任线：能输入任意路径 SPAWN 的人，看到文件夹名不多知道什么；安全沙箱开启时只列沙箱根内，父级止于沙箱根，与 SPAWN 的校验一致。
- 远程端（`src/remote/folderBrowser.ts` + `openOnPc.ts`）：打开文件夹 = 快速输入里的 PC 文件夹浏览器（"打开此文件夹"、`..`、子文件夹、PC 最近打开的文件夹、盘符；也可直接输入 PC 上的绝对路径）→ 已有窗口显示它就进入那个窗口，否则 `SPAWN` 新窗口，注册后窗口切换器的生命周期监视自动进入。本窗口的 `open_folder` 继续被门禁拒绝——本窗口的根就是会话的文件边界，扩大它是 SPAWN 的事。
- 副本（PC 窗口被观看时）：`pickFolder` 改走窗口内的同一个浏览器（数据源是 PC 自己的 `list_dir`），浏览器作为 DOM 出现在副本里，B 看得见、点得到；选中后在这个 PC 窗口里打开。原生对话框只在没有观看者时弹出。
- 接线是 `platform/hooks.ts` 的 `folderOpen` 扩展点：会话装"浏览 PC + SPAWN"，桌面装"有观看者时窗口内浏览"，都没有时走原生对话框。
- 窗口切换器的"新窗口…"改用同一个浏览器（取消选择仍开空窗口，保持原语义）。
- 测试：daemon `http::browse` 单测 4 条 + `tests/integration.rs` 的 `the_folder_browser_needs_a_session_and_the_folder_input_switch`；`tests/remote.test.ts` 的 "Open Folder on the PC" 组 5 条；`tests/remoteWorkbenchSync.test.ts` 的菜单裁剪扩展与"会话打开文件夹走 PC 浏览器、从不调 `open_folder`"。

### 6.2 窗口

- 窗口切换器成为远程端的"文件"菜单的核心：列出 PC 上全部窗口（摘要、状态徽标），操作为进入 / 关闭 / 重启 / **在新窗口打开文件夹…**（PC 浏览器）。
- 窗口选择页（守护进程 `web/picker.js`）的"输入路径"行换成同一个 `api/browse` 浏览器（P1）——手机上不必再手输路径。

### 6.3 传输

- 只在远程端：上传（选 B 的文件 / 文件夹，分块续传，失败逐个汇报）、下载、下载为 Zip（现状的 `src/remote/transfer.ts` 与守护进程票据下载）。
- 远程外壳里传输入口集中在三处：文件页的 action sheet、资源管理器行的上下文菜单、编辑器页的"下载此文件"。
- 本地见 §5 末段。

## 7. 同步分级与流量预算

每一类状态归入一档。"跨端"指同一窗口的不同前端之间（PC 桌面界面 ↔ 远程界面，或两个远程界面）。

| 档 | 含义 | 机制 | 成员 |
| -- | ---- | ---- | ---- |
| **S 必须同步** | 一端变了，另一端必须马上一致，否则两人看到的是不同的事实 | 推送：后端事件 + `studio://workbench-sync`（每条 ~100 B）；文档内容走后端的唯一副本 | 文档内容与保存状态（同一份后端缓冲）；打开 / 关闭 / 活动的编辑器标签；工作区文件夹集合；文件系统变化（watcher 批次，只带路径）；SCM 状态（计数 + 已展开组的行）；终端输出（只推给打开了该终端的前端）；扩展 webview 页（§22.6 的流式副本，经济化的 DOM 增量）；需要回答的提示（未保存确认、扩展的 `showQuickPick` / `showInputBox` 路由到发起的前端）；通知（标题 + 级别，详情按需） |
| **D 按需拉取** | 只有这一端在看时才过线，看完不再推 | 请求-应答 + Service Worker 缓存（哈希资产永久缓存，带版本的数据短缓存） | 目录列表（展开才拉，大目录分页 `list_dir_page`）；文件内容（打开才拉，大文件窗口化，阈值为桌面的 1/16）；搜索结果（流式首屏，滚动续拉）；Git Graph 的提交行（虚拟列表的可见窗口）；差异（打开 diff 才算）；符号、大纲、悬停、补全（请求即算即弃）；扩展详情页、README；问题列表的全量（徽标数是 S 档） |
| **L 只在本端** | 各端自己的显示状态，永不过线 | 本地内存 / `localStorage`（scopedStorage） | 布局尺寸（侧栏宽、面板高、分栏）；滚动位置；折叠 / 展开状态；光标与选区（除非协作需要，见 §10 Q-d）；主题、字号、缩放；悬停、动画、光标闪烁、过渡；小地图、粘性滚动、括号着色等可由文档本地推导的装饰；命令面板与快速输入的输入过程；标题栏 / 状态栏的本地项 |

规则：

- **S 档只发操作与差量**：文档编辑发 CodeMirror 的变更集（不是全文）；终端发输出字节（brotli 后过线，省流模式下合批 250 ms）；SCM 发变化行。
- **D 档带版本**：每个拉取的响应带内容哈希或 mtime，远程端缓存命中即 304 / 零字节（目录列表、文件内容、扩展资源）。
- **L 档的跨端行为**：两端各自滚动、各自折叠；"打开一个文件"会同步，但打开后各自停在自己的滚动位置（锚点行例外：跳转到定义 / 搜索结果的行锚点随 open 一起过线，现状）。
- **省流模式**（`data-data-saver`）在 D 档上再收紧：图片与 webview 资源按需点开、Git Graph 只拉可见窗口不预取、搜索首屏 50 条、终端输出合批 1 s、扩展 webview 副本降到 1 Hz 采样。

**预算**（P4 由 `tests/remoteTraffic.test.ts` 扩展场景与 `scripts/probes/remote-live-check.mjs` 实测；数字是验收线，不是愿望）：

| 场景 | 下行预算 | 今天（副本） |
| ---- | -------- | ------------ |
| 空闲 60 s（窗口开着，什么都不做） | ≤ 2 KB（心跳 + 摘要） | 取决于 PC 画面上的动画（光标闪烁、状态栏计时器） |
| 打开一个 200 KB 文件并滚动浏览 30 s | ≤ 60 KB（内容一次，压缩后） | 副本：可见行 DOM + 每次滚动的视口替换 |
| 编辑 50 次按键 | ≤ 5 KB 上行 + ≤ 3 KB 下行 | 副本：每次按键的 DOM 回显 |
| Claude 流式回复 12 s / 360 token | ≤ 7 KB（维持 §22.8 的经济化） | 7.0 KB |
| Git Graph 快速滚动 2 s | ≤ 7 KB | 6.8 KB |

## 8. 副本模式的新位置

副本（§22）当初成为默认，理由是独立工作台刷新会丢 Claude 的对话状态（§22.1）。§22.6 之后，扩展 webview 在独立界面里也已是 PC 上那一份的流式副本——刷新只重连副本，对话不丢。这条理由已不成立，所以：

- **默认**：远程端一律进入远程外壳（独立界面）。`uiMode.ts` 的 auto 规则改为 `wantsOwnUi = request !== 'mirror'`。
- **"查看 PC 屏幕"**（`remote.liveView`，抽屉 / 用户菜单里的一行，`?mirror=1`）：显式进入副本，用于"看 PC 上正在发生什么"——例如看一个只在 PC 上弹出的原生对话框、看 PC 上的布局。副本里同样适用 §5 的远程命令配置（P0 已让 PC 窗口在有观看者时隐藏新窗口 / 打开文件 / 打开工作区，"打开文件夹"走窗口内浏览器）。
- 副本不再改 PC 窗口：手机观看时不再换手机外壳、不再缩窗口——副本以 PC 的原样缩放显示（可双指放大），PC 前的用户不受影响。`phoneShell.ts` 与 `remote_mirror_fit` 的手机路径在 P3 删除。
